# 脚本能力只经宿主函数提供（半托管沙箱）

- 状态：`已接受（API 明细待收敛）`
- 日期：2026-09-18
- 关联：[ADR 0001](0001-no-shared-state-in-v1.md)、[ADR 0003](0003-script-first-multi-runtime.md)

## 背景

运行时改为进程内嵌入（Boa + RustPython）后，脚本与 Mock 服务同处一个进程。语言运行时自身的能力（Node 风格的全网络栈、Python 的 `os`/`socket`/`subprocess`）一旦暴露给脚本，宿主就没有拒绝的余地：SSRF、任意文件读写、拖死主进程的循环，全部直接生效。

三条路线：极简（只给必需的几个宿主函数）、半托管（宿主函数 + 请求内暂存 + 日志 + 重试参数）、全托管（把引擎原生 `fetch`/`fs`/`console` 直接开放，宿主做事后过滤）。

## 决策依据

1. 嵌入 Boa 后不存在"杀掉子进程"这种廉价逃生通道，隔离必须由 API 形状提供，而不是由事后过滤提供。
2. boa_runtime 自带裸 `fetch`（`FetchExtension` + `BlockingReqwestFetcher`）。裸 fetch 与"域名白名单"互斥：一旦脚本能拿到它，白名单就只是建议。
3. RustPython 侧同理：`os.system`、`socket`、`subprocess` 必须从可导入模块中移除，而不是靠运行时拦截。

## 决策

脚本能看到的全部外部能力，**只能来自宿主注入的函数**（半托管模式）。引擎自带的网络、文件、子进程能力一律不注册进脚本上下文。

具体边界：

- 网络：只有 `ctx.http.*`，宿主校验白名单后才发请求。boa_runtime 的 `fetch` 不注入。
- 文件：只有 `ctx.file.*`，路径限定在**静态文件目录**（配置声明的唯一文件根，见 CONTEXT.md）内，相对路径解析到该根。不注入 `require`/`fs`；Python 侧移除 `os`/`subprocess`/`socket` 的导入能力。上传文件由宿主解析到系统临时目录下的每请求随机子目录（Unix `0700`，路径不暴露给脚本），请求结束清理；静态文件目录仍是 `ctx.file` 可寻址文件的唯一根。
- 时间：允许 `setTimeout`/`setInterval`（boa_runtime `interval`），但受脚本整体超时约束。
- 输出：只有 `ctx.respond(...)` 与流的透传原语能写客户端；`console.log` 只进服务端日志。
- 跨请求数据：不提供（ADR 0001）。请求内暂存单独命名，避免与共享状态混淆。

## T12 修订

multipart 上传临时目录使用系统临时目录，而不是静态文件根下的子目录：这样上传写入不依赖、也不污染脚本可读根，且脚本从未获得任何临时路径。`ctx.request.files` 只暴露宿主 handle 与 basename 元数据；静态文件目录仍是脚本可寻址文件的唯一根。2026-09-23 由 T12（#53）落地。

## 后果

**正面**：沙箱承诺可写成一句话——"脚本能做的事等于 API 列表里的事"；域名/路径/超时/内存四类限制都有唯一实施点；将来把某个宿主换成真实运行时，脚本可不改。

**负面（接受）**：用户不能直接复用现成的 Node/Python 代码，需要改写为宿主调用；宿主函数成为产品的公开契约，删除或改名是破坏性变更；表达力受宿主覆盖面限制（例：脚本无法自行发起 TCP/UDP 连接）。

**约束**：宿主 API 是产品对外契约的一部分，必须版本化并提供 `.d.ts` 类型定义；新增宿主函数默认按"能力扩张"对待，需评估沙箱影响。

## 替代方案

- 极简模式（拒绝：重试与日志是高频需求，压回用户自实现会立刻侵蚀体验）
- 全托管模式（拒绝：与进程内嵌入组合后无法可靠封堵，事后过滤不是安全边界）
